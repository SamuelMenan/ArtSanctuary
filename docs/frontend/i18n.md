# i18n

Sistema homegrown sin librería. Diccionario flat en `src/shared/i18n/`, 2 locales (es default + en).

## API

```ts
import { createTranslator, getDictionary, type Locale } from '@/lib/i18n'

const t = createTranslator(getDictionary(locale))
t('settings.profilePublic')                  // → 'Perfil público' (es)
t('home.welcomeBack', { name: 'Esteban' })   // → 'Bienvenido de nuevo, Esteban'
```

`createTranslator` devuelve función `(key, vars?)` que:
- Resuelve key dot-separated (`'settings.appearance'` → `messages.es.settings.appearance`).
- Si no encuentra string, devuelve la key como fallback (debug-friendly).
- Sustituye `{{var}}` en el resultado.

## Server vs client

### Server Components

```tsx
import { auth } from '@/auth'
import { createTranslator, getDictionary } from '@/lib/i18n'
import { getRequestLocale } from '@/lib/requestPreferences'

export default async function Page() {
  const locale = await getRequestLocale()
  const t = createTranslator(getDictionary(locale))
  return <h1>{t('home.heroTitle')}</h1>
}
```

`getRequestLocale()` lee la cookie `artsanctuary-locale`. Default `es`.

### Client Components

Dos opciones:

**Opción A — recibir `t` por props** (preferida cuando un server component lo crea):

```tsx
interface Props { t: (key: string, vars?: Record<string, string | number>) => string }
export function ProfileForm({ t, initial }: Props) { ... }
```

`t` es función serializable de RSC. Funciona porque es closure puro.

**Opción B — `usePreferences()` desde provider**:

```tsx
'use client'
import { usePreferences } from '@/components/AppPreferencesProvider'

export function MyComponent() {
  const { t, locale } = usePreferences()
  return <span>{t('common.save')}</span>
}
```

Usar cuando el componente es client-side puro (sin server padre que cree `t`) o
necesita reaccionar al cambio de locale en vivo.

## Cambio de locale

`AppPreferencesProvider.setLocale(next)`:

1. Set state local.
2. Escribe cookie `artsanctuary-locale` (max-age 1 año).
3. Escribe `localStorage` (defensivo).
4. Fire `PATCH /api/preferences` si hay sesión.
5. `router.refresh()` → re-renderiza server components con nuevo locale.

## Estructura del diccionario

`src/shared/i18n/dictionaries.ts` define `messages` con shape `{ es: {...}, en: {...} }`. Agrupado
por dominio:

```ts
{
  common: { save, cancel, delete, edit, ... },
  nav: { home, gallery, explore, profile, ... },
  menu: { dark, light, language, ... },
  home: { heroTitle, recentWorks, welcomeBack: 'Bienvenido de nuevo, {{name}}', ... },
  gallery: { all, noResults, title, ... },
  explore: { searchTitle, placeholder, filters, ... },
  profile: { editProfile, followsYou, portfolio, bio, location, ... },
  settings: { profilePublic, deleteAccount, changeEmail, ... },
  upload: { autofill, category, submit, ... },
  auth: { loginTitle, signIn, password, ... },
  modal: { editMetadata, comments, ... },
  sidebar: { noCollections },
}
```

## Convenciones de keys

- **dot.separated**: `<domain>.<key>` (e.g. `settings.deleteAccount`).
- Sin redundancia: `settings.deleteAccount`, no `settings.settingsDeleteAccount`.
- **Variables `{{var}}`**: case-sensitive, kebab-incompatible. Usa camelCase.
- **Mensajes completos**: nunca concatenar fragmentos traducidos (`t('hello') + ' ' + name` → mal). Usar interpolación.

## Añadir locale nuevo

1. Extender tipo `Locale` en `src/shared/i18n/`: `'es' | 'en' | 'pt'`.
2. Añadir `messages.pt` con el mismo shape que `es`.
3. Actualizar `normalizeLocale(locale)`.
4. Añadir opción en `AppearanceForm.tsx`.
5. Verificar fallback: keys faltantes vuelven a la key literal.

## Tooling

### Detectar claves huérfanas (no implementado)

Idea pendiente, sin herramienta que lo haga hoy: comparar las keys del
diccionario contra los usos de `t('...')` en el codebase y reportar:
- Claves definidas pero no usadas.
- Claves usadas pero no definidas.
- Claves en `es` no traducidas en `en`.

### Lint manual

```bash
grep -roE "t\(['\"][^'\"]+['\"]" app components | sort -u
```

Lista todas las keys referenciadas. Comparar contra `src/shared/i18n/dictionaries.ts`.

## Anti-patterns

❌ Hardcode literal en JSX (`<button>Guardar</button>`).
❌ Concatenar traducciones (`t('hello') + ' ' + name`).
❌ Usar key como fallback final visible al usuario (eg `'settings.foo'`). Si la
   key aparece literal, hay un missing key — corregir.
❌ Traducir errores de validación duplicando lógica entre cliente y servidor.
   El servidor devuelve mensajes ya localizables a través de `error.fields`;
   el cliente decide si mostrar el mensaje del servidor o un wrapper local.
